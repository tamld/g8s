5-stage cognitive execution loop

A self-correcting task lifecycle driving agents from raw natural language intent to permanent institutional case-law maturation.

Stage 1: Covenant Intake & Sealing

Natural language prompts are notoriously prone to context degradation. Stage 1 takes incoming requirements and parses them into a tamper-evident covenant contract sealed with an out-of-band SHA-256 promise digest.

The covenant establishes unambiguous boundary definitions: explicit forbidden operations, whitelist file paths, required test assertions, and maximum token budgets before execution is authorized.

Key Invariants & Defenses
  • Target Failure: Long-horizon prompt drift and constraint amnesia.
  • Guarantee: Immutable promise anchor; prompt cannot silently change during execution.
  • Artifact: Signed SHA-256 Covenant Token Baton injected into every subsequent subtask.

Stage 2: Disjoint DAG Decomposition

Monolithic agent runs fail because subagents develop horizontal dependencies and step on each other's files. Stage 2 enforces the Cardinality Law: 1 issue = 1 worker = 1 receipt.

The covenant is decomposed into a directed acyclic graph (DAG) of isolated work packets. Subagents operate with zero direct horizontal communication, sharing state only through frozen briefs and disjoint receipts.

Key Invariants & Defenses
  • Target Failure: Conflicting file edits, race conditions, and uncontrolled blast radius.
  • Guarantee: Strict isolation: workers never coordinate horizontally.
  • Artifact: Single-use, path-scoped write authorization receipt per DAG node.

Stage 3: 5D Adversarial Debate

Before writing a single line of code, the implementation plan is submitted to five orthogonal automated personas: Systems Architecture, Security Red Team, Causal Memory, Spatial UX Physics, and Minimalist SRE.

The personas engage in multi-round thesis, antithesis, and synthesis stress testing. Candidate implementation choices are simultaneously ranked against the 5D Causal Memory Graph to identify known failure precedents.

Key Invariants & Defenses
  • Target Failure: Premature implementation of flawed designs and blindspot oversights.
  • Guarantee: Code execution cannot start while unresolved counterexamples remain.
  • Artifact: Falsification Ledger and Causal Precedent Ranking Scorecard.

Stage 4: Monotonic Verification

During code generation, Aegis enforces a monotonic quality ratchet. Verification is continuous: test pass rates, contract assertions, and coverage baselines can never decrease.

If an agent attempts a shortcut—such as commenting out an assertion or introducing a mock stub—the Crucible intercepts the physical diff immediately. Execution rewinds to the last verified checkpoint or forks an alternative branch.

Key Invariants & Defenses
  • Target Failure: Assertion pruning, test skipping, and regressions in existing functionality.
  • Guarantee: Non-regression guarantee: work never moves forward if high-water marks decrease.
  • Artifact: Physical diff evidence logs and unforgeable Round Receipts.

Stage 5: Meta-Learning Retrospective

Autonomous sessions typically terminate tabula rasa, losing everything learned during execution. Aegis closes the loop by transforming verified ticket outcomes into permanent institutional memory.

Enforcing synaptic homeostasis, lessons must prove measurable ROI in preventing repeats or be automatically retired. Every executed ticket systematically updates system precedent weights.

Key Invariants & Defenses
  • Target Failure: Systemic amnesia and repeating identical debugging errors across sessions.
  • Guarantee: Closed-loop maturation: historical solutions permanently guide future agents.
  • Artifact: Structured Reflection Receipt promoting verified case law to the 5D Graph.

Integrity

Truth above all. Deleting test assertions, faking green test results, or hiding failures is strictly forbidden.

Rank 2 • Weight 5
